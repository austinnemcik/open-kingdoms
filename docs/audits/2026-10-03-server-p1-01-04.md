# Audit: server PRs #2–#5 (auth, persistence, clock, production)

Reviewed against main @ 7f3239b. Fix task: ROADMAP **P1-H1**.

## High

1. **Unknown building kind in persisted data permanently breaks the server.**
   `kingdom-server/src/state.rs` `to_view` uses `.expect("cities only contain validated building kinds")` while holding the global store `Mutex`. Removing/renaming a kind in `data/` → first `get_city` panics → mutex poisoned → every login/resume/get_city returns `Internal` until restart.
   Fix: never panic on persisted data (skip + log unknown kinds), build the view outside the lock, recover from poisoning (`unwrap_or_else(|e| e.into_inner())` or `parking_lot`). Test: city containing an unknown kind.
2. **Argon2 runs inside the global store lock → login-flood DoS.**
   `state.rs` `login()` hashes/verifies while holding `store.lock()` (~16 ms each in release). ~60 logins/s from many connections stalls every player; blocking-pool threads pile up.
   Fix: read account under lock → release → hash/verify → re-lock to write. Semaphore for concurrent hashing; per-IP + per-account login rate limits; registration cap per IP.

## Medium

3. **No connection limits.** `session.rs` `run()`: no hello/login deadline, `ping` keeps unauthenticated sockets alive forever, no message rate limit after login (each `get_city` = global lock + DB write), no global/per-IP connection cap.
   Fix: 10 s handshake deadline, idle timeout, per-connection token bucket in all phases, connection caps, answer `ping` without `spawn_blocking`.
4. **Session tokens never expire and are stored in plaintext** (`store.rs` `save_session`, `migrations/001_initial.sql`). DB leak = permanent account takeover; rows accumulate forever.
   Fix: store SHA-256(token), `created_at`/`expires_at`, prune, cap sessions per player (new migration).

## Low

5. `session.rs` `authenticated()` maps every error (incl. `Internal`) to `InvalidCredentials` and counts it as a failed attempt. Propagate `Internal`.
6. `city_view` load → collect → save is only safe because of the global lock; keep it one critical section / SQLite transaction when narrowing locks.
7. Missing tests for 1–3.

## Verified fine
Collect math (u128, remainders, backwards clocks), data validation, transactional migrations, parameterized SQL, 32-byte OS-RNG tokens, 4 KiB frame cap, protocol versions match, game-core purity.
